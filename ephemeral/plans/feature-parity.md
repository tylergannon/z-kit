# Feature and test parity map

Research and roadmap reference, not an implementation checklist. The [current build brief](mapping-contract.md) controls the supported mapping and first slice; Go mechanisms and later capabilities below are evidence, not extra gates. Publication/cache correctness now belongs to the first generator; schema/provider/manual-schema, numeric-enum and time features remain deferred. Public backend SDKs and barrels are not requirements.

Primary: [mapping proposal](mapping-contract.md). Acceptance: [one example](example-acceptance.md). Provenance: [ledger](mapping-evidence.md). All links use inspected peer Go Polytype commit **`c9ae9678816768776569e1157bd3c4372e1be5c6`**. **Every peer test below is source-inspected, not executed in this task; every Zig acceptance case is proposed and unexecuted.** “Parity” tracks behaviors and deliberate differences, not a completed port or an obligation to copy Go mechanisms.

Stages: **A** = first primitive/record projection checkpoint; **B** = bounded typed devalue exchange in the same example; **Later** = subsequent supported capability; **Refuse** = intentionally outside initial shared admission. TS and JSDoc have equal standing at A/B. Later does not imply a backend exists today. Focused invalid/numeric/printer tests need not enlarge the public example's central model.
